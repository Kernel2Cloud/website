Ship a container, get an endpoint

Tell us the image, the port, how many GPUs each copy needs and how many copies to run. We handle placement, health and rollouts.

deployment.jsoncall.sh
// one copy = one server's worth of GPUs, or less
{
  "name": "chat",
  "image": "vllm/vllm-openai:latest",
  "args": ["--model", "Qwen/Qwen2.5-72B-Instruct",
           "--tensor-parallel-size", "2"],
  "port": 8000,
  "gpus_per_replica": 2,
  "replicas": 3,
  "health_path": "/v1/models"

# then call it with your API key
curl https://chat-acme.apps.kernel2cloud.ai/v1/models \
  -H "Authorization: Bearer $K2C_API_KEY"

Platform

Built to run GPUs in places that aren't data centers

Racks sit on residential power and internet, in places we don't physically control. The platform is designed around that.

One pool, many sites

The scheduler treats every rack as part of a single on-demand pool.

How it places work
  • Each copy lands on one server with enough free GPUs
  • Copies of a deployment are spread across racks
  • Rollouts replace one copy per pass and pause when a new version can't start
  • Each buyer gets whole servers; nobody shares a machine

GPU health from NVIDIA DCGM

Every GPU reports its health continuously, and problems become alerts for our operators.

What we do with it
  • GPU health alerts straight from DCGM telemetry
  • Servers with problems are cordoned and drained, and their copies move elsewhere
  • When a site loses power or cooling, the pool shrinks instead of failing
  • All rack metrics are kept centrally for every site

Security for untrusted places

A rack in a backyard has to protect itself, so security starts at boot.

Layers
  • Immutable operating-system image on every server, with secure boot and TPM
  • New racks register themselves and wait for an operator's approval
  • Whole servers per buyer, on hardened Kubernetes
  • Endpoints only answer requests carrying the buyer's API key
  • Buyers can't override GPU driver settings from their containers

An operations console for the fleet

Our team runs every site from one place.

Tools
  • Fleet map with each rack at its site
  • Hardware inventory read from the servers themselves
  • Remote terminals on racks, without opening ports at the site
  • An audit log of approvals, cordons and deployments

FAQ
What GPUs do you run?

NVIDIA RTX PRO 6000 Blackwell with 96 GB each. Every rack has one server with 8 to 16 of them — 768 GB to 1.5 TB of GPU memory — connected over PCIe.

How large a model can I run?

One copy runs on one server, so up to 16 GPUs and 1.5 TB of GPU memory per copy (more with FP4 weights). Models that span several servers aren't offered yet. Run more copies to serve more traffic.

What happens if a site goes offline?

Copies of your deployment run on different racks, and the gateway sends traffic only to copies that are ready. If a rack drops off, the others keep answering while the scheduler replaces the missing copy.

Do I share servers with other customers?

No. Each buyer gets whole servers, and you only see your own deployments and logs.

How is compute priced?

Pricing depends on your workload. Get in touch and tell us what you need.

What do I need to host a rack?

A dry, covered space with a suitable electrical supply. We provide the hardware and the internet connection, and assess every site before installing.
